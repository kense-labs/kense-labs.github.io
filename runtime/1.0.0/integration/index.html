接入 MAIN

接入 Main

装包、起控制面、放置、跑通会话。

更新 2026-11-14 文档版本 1.0.0 默认

读者：能改 Main 启动配置与薄代理的人。还没跑通过？先花一分钟完成 1 分钟对接。概念与分层见 边界与分工。已有本机旁路时先看 迁出本机旁路。

目标：在控制面已活的基础上，放置正确、最小会话跑通。宿主能力和共享是可选增强，不是主路径。

装包

install.shbash
pnpm add @kense/krun
能力用法
控制客户端KrunClient.fromEnv() / client.doctor()
低级 RPCcontrolCall(endpoint, method, params)
控制端点resolveControlEndpoint() / CONTROL_ENDPOINT_ENV
二进制resolveKrunBinary()；也可设 KRUN_BIN
起控制面spawnKrunServe({ bin, dataDir, … })
合同loadContract('…') / listContracts()

起控制面

  1. resolveKrunBinary()；找不到就失败，不要静默跳过。
  2. 为进程准备控制端点（CONTROL_ENDPOINT_ENV）与数据目录。
  3. spawnKrunServe；它不会等就绪——Main 自己轮询 doctor。
  4. 就绪后再谈会话。

可复制片段见 调用配方 · 起控制面。

放置与会话

放置含义发版
本机旁路业务进程在宿主直接跑仅调试
隔离运行时业务进程在 Runtime 隔离环境默认

强制隔离时，缺会话端点必须启动失败，禁止回退本机旁路。

典型顺序：validate（或已有 pin）→ session.activate → 用返回的会话端点拨产品会话 → 结束后 session.deactivate。字段表在 控制面 API；按任务抄代码在 调用配方。

验收这一步

  1. @kense/krun 已装，二进制能解析。
  2. doctor 通。
  3. 放置完成且持有会话端点。
  4. 最小一轮对话通过。
  5. 断线与失败行为符合产品预期。

宿主能力（可选）

主路径过了再开。入口是 host_tools/prepare，再 host_call / host_cancel。细节：调用配方 · 宿主工具、控制面 API。

  1. 按合同准备能力目录。
  2. 只开放需要的工具名（如 Read、Write、Edit、Grep、Bash）。
  3. 业务侧只看见工具名。
  4. 未准备好时拒绝该工具，不拆整轮会话。

工作区共享（可选）

概念含义业务侧可见
业务私有卷隔离环境内单写持久卷稳定路径
工作区共享按 share_id 增删含 share_id 的稳定路径
工具根Main 侧文件能力授权根不可见

调 guest_shares/*。业务可见数据里不能出现宿主绝对路径。

状态映射

Main 把运行状态映射成界面只读字段。控制方法名、端点、密钥不得进界面。形状见合同与 控制面 API · 产品状态面。

对接验收

  1. 只有 Main 依赖 @kense/krun。
  2. 界面与业务进程不出现 Runtime 私有标识。
  3. 放置为默认隔离或强制隔离；缺端点启动失败。
  4. 最小会话通过。
  5. 若开了能力 / 共享：行为符合合同。
  6. 无 Runtime 时，界面状态为不可用。

出门清单：发版检查。
