边界与分工

边界与分工

谁调 Runtime、谁不调、术语从哪来。建议先完成 1 分钟对接。

更新 2026-11-14 文档版本 1.0.0 默认

建议先完成 1 分钟对接：控制面活了再回来看分层。本页说明分工与术语，不是入门拦路石。

读者：Web Main。界面与业务进程不直接对接 Runtime。

Runtime 做隔离执行、产品会话转发，以及可选的宿主能力中继与工作区挂载。对话、编排和业务语义留在 Web。对接只发生在 Main，客户端与合同从 @kense/krun 来。

本站只交付文档；二进制和合同跟着包走。

谁做什么

层负责不负责
界面产品状态与业务数据端点、密钥、控制方法名、@kense/krun
Web Main装包、放置、会话端点、控制面、状态映射把端点或密钥原文交给界面
业务进程回合、工具名、稳定工作区路径控制面；宿主绝对路径
Runtime隔离执行、会话转发、可选中继与卷产品业务语义

从包拿什么

install.shbash
pnpm add @kense/krun
能力说明
KrunClient绑定端点的控制客户端（优先）
controlCall低级一行 JSON RPC
contracts/与产品同步的 JSON 合同
resolveKrunBinaryoptional 平台包或 KRUN_BIN

接线步骤：接入 Main。字段与错误码：控制面 API。按任务抄代码：调用配方。

术语

术语含义
放置Main 决定业务进程走本机旁路还是隔离运行时
会话端点Runtime 给出的拨号目标；Main 用它建产品会话
本机旁路业务进程在宿主直接跑；仅调试
隔离运行时业务进程在 Runtime 管的隔离环境里跑；发版默认
宿主能力按合同开放、经 Runtime 中继的宿主侧工具
工作区共享按 share_id 挂到隔离环境的工作区
合同包内 contracts/ 的能力名单与状态字段形状

按任务打开

你要做的事打开
第一次对接（约 1 分钟）1 分钟对接
完整接入 Main接入 Main
已有本机旁路，要切隔离迁出本机旁路
完成某件事该怎么调调用配方
查参数 / 错误码控制面 API
出门前核对发版检查
01接入 Main装包、起控制面、放置、跑通会话→02边界与分工谁调 Runtime、谁不调、术语从哪来（跑通后再读）→03迁出本机旁路从宿主直跑切到隔离运行时→04调用配方按任务写好的 Main 调用路径，附可运行片段→05控制面 API方法、参数、错误码与状态面→06发版检查可见范围、版本钉扎、出门清单→
