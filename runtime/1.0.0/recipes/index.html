调用配方

调用配方

按任务组织的 Main 调用路径：什么时候用哪条 API，以及可落地的代码片段。

更新 2026-11-14 文档版本 1.0.0 默认

读者：改 Web Main 薄代理的人。第一次？先 1 分钟对接。需要字段定义时去 控制面 API；完整接线走 接入 Main。

怎么用本页： 先对上你的任务，再抄对应片段。不要把整页当清单勾完——多数产品路径用不到回收、能力租约或目录授权。

先分清两件事

你在找去哪
「这个方法参数叫什么、失败码是什么」控制面 API
「我想完成某件事，该按什么顺序调」本页

有 KrunClient helper 的优先用 helper；没有的用 client.call(method, params)。成功拿 result，失败拿 KrunControlError.code。

---

起控制面并确认活着

二进制找不到就别往下走。spawnKrunServe 不会替你等就绪——Main 自己轮询 doctor。

main/boot.tstypescript
import {
  resolveKrunBinary,
  spawnKrunServe,
  KrunClient,
  CONTROL_ENDPOINT_ENV,
} from '@kense/krun';

const bin = resolveKrunBinary();
if (!bin) throw new Error('krun binary missing');

const dataDir = process.env.KRUN_DATA_DIR!;
const endpoint = process.env[CONTROL_ENDPOINT_ENV]!;
spawnKrunServe({
  bin,
  dataDir,
  env: { [CONTROL_ENDPOINT_ENV]: endpoint, KRUN_DATA_DIR: dataDir },
});

async function ready(ms = 15_000) {
  const until = Date.now() + ms;
  for (;;) {
    try {
      return await KrunClient.fromEnv().doctor();
    } catch (err) {
      if (Date.now() > until) throw err;
      await new Promise((r) => setTimeout(r, 50));
    }
  }
}

await ready();

doctor 结果给运维/门禁用。不要把 backends 原文塞进界面。

装包 → 开会话 → 收会话

发版路径用 local_zip。request_id 是幂等键，别每次乱飘除非你故意开新请求。

main/session.tstypescript
import { KrunClient } from '@kense/krun';

const client = KrunClient.fromEnv();

const { digest: pin } = (await client.call('validate', {
  path: '/abs/path/harness.zip',
})) as { digest: string };

const { generation } = (await client.session.activate({
  harness: { id: 'demo', source: 'local_zip', pin },
  request_id: 'turn-42',
  task_id: 'task-1',
  tools_admitted: ['Read', 'Write', 'Edit', 'Grep', 'Bash'],
  workspace_bind: { mode: 'local_mount', path: '/abs/workspace' },
  workspace_binding: 'ws-1',
})) as { generation: number };

// 产品会话拨的是 Runtime 给出的会话端点，不是控制面方法

await client.session.deactivate({ task_id: 'task-1', generation });

关掉会话之后，同一 generation 再 host_call 必须失败关闭。这是合同，不是「尽量」。

需要换 harness 而不拆产品任务时，走 handoff_prepare → handoff_commit（或 handoff_abort）。冲突码见 API 页的 handoff_*。

宿主工具：先授权，再代发

平面 A 的入口是 host_tools/prepare。没有 grant，就不要假装工具可用。

main/host-tools.tstypescript
import { KrunClient, PERMISSION_NEQ_SCOPE } from '@kense/krun';

const client = KrunClient.fromEnv();

await client.hostTools.prepare({
  task_id: 'task-1',
  runtime_generation: generation,
  workspace_binding: 'ws-1',
  expires_at_ms: Date.now() + 30 * 60_000,
  // tools_admitted: ['Read', 'Bash'], // permission only — ≠ path scope
});
void PERMISSION_NEQ_SCOPE;

// 无 helper：代发 / 取消
await client.call('host_call', {
  task_id: 'task-1',
  generation,
  call_id: 'w-1',
  name: 'Write',
  arguments: { file_path: 'out.txt', content: 'ok\n' },
});

try {
  await client.call('host_cancel', {
    task_id: 'task-1',
    generation,
    call_id: 'w-1',
    name: 'Write',
    arguments: { file_path: 'out.txt', content: 'ok\n' },
  });
} catch {
  // 取消成功只表示控制面不再认这笔调用；远端进程未必已死
}

只要 generation 变了，旧 grant 作废。凭据平面和工具根（setRoots）不是一回事。

host_endpoint 只给 Main 拿拨号信息，别泄漏。

工作区共享与资源旋钮

共享：参数里禁止 host_path。业务侧只看见带 share_id 的稳定 guest 路径。

main/shares.tstypescript
import { KrunClient } from '@kense/krun';

const client = KrunClient.fromEnv();
await client.guestShares.add({ name: 'vm-main', share_id: 'workspace' });
await client.guestShares.list({ name: 'vm-main' });
await client.guestShares.remove({ name: 'vm-main', share_id: 'workspace' });

资源：set / adjust 只改 desired。看到 needs_restart 再 recreate，不要在文档或 UI 里写成「已经热扩容」。

main/resources.tstypescript
import { KrunClient } from '@kense/krun';

const client = KrunClient.fromEnv();
await client.vmResources.set({
  cpus: 4,
  memory_mib: 4096,
  disk_mib: 20480,
  profile: 'manual',
  name: 'vm-main',
});
const st = (await client.vmResources.status({ name: 'vm-main' })) as {
  apply_state?: string;
};
if (st.apply_state === 'needs_restart') {
  await client.vmResources.recreate({ name: 'vm-main' });
}

Core 实现选择同理：coreImpl.set({ impl: 'default' })；未知 id 失败关闭。切实现后旧 host_tools lease 不能继续用。

较少用到的面

这些不是主路径。用之前先确认产品真的需要。

任务入口
能力租约capabilities/open → call / execute → close（client.call）
目录授权`directories/grant\update\revoke\list`
清孤儿 / 卸 pinreclaim_orphans、reclaim_pin、uninstall_pin、gc_pins
出站 Authzegress/status · egress/admit · egress/revoke（client.call；EGRESS_CLAIMED_DEFAULT === false）
生命周期观测client.lifecycle.events({ since_seq })
读合同loadContract / loadHostCapabilityScopes / loadHostCaps*

capabilities/* 执行期可能冒出内部 provider/call——那是回调，不是产品 API。

出站：admit 本身不开网。不要把「控制面调通」写成「出站已合格」。

main/egress-lifecycle.tstypescript
import {
  KrunClient,
  EGRESS_CLAIMED_DEFAULT,
  type EgressAdmitRef,
} from '@kense/krun';

const client = KrunClient.fromEnv();
void EGRESS_CLAIMED_DEFAULT; // false

await client.call('egress/status', {});
const ref: EgressAdmitRef = {
  scope: 'tools_mediated',
  task_id: 'task-1',
  generation,
};
await client.call('egress/admit', { ...ref });
await client.call('egress/revoke', { ...ref });

let since = 0;
const page = await client.lifecycle.events({ since_seq: since });
for (const ev of page.events as { seq: number }[]) {
  since = Math.max(since, ev.seq);
}

出错时怎么分支

main/errors.tstypescript
import { isKrunControlError } from '@kense/krun';

try {
  /* await client.… */
} catch (e) {
  if (!isKrunControlError(e)) throw e;
  switch (e.code) {
    case 'missing_endpoint':
    case 'transport':
    case 'timeout':
      // 控制面没起来或断了
      break;
    case 'invalid_package':
    case 'pin_mismatch':
    case 'acp_negotiate_failed':
      // 包装 / 协商
      break;
    case 'handoff_conflict':
    case 'handoff_failed':
      // 热切换
      break;
    case 'fail_closed':
    case 'session_revoked':
    case 'unauthorized':
      // 拒写、撤权
      break;
    default:
      // 映射成产品侧失败态；别把内部 code 原文甩给终端用户
      break;
  }
}
